## Reading these results together

The checkpoint and race tests identify where older state and check-before-write authorization survive revocation. Custody and code-binding tests ask which source information the recipient can trust. The independent-recipient test separates the owner's revocation event from the downstream acknowledgment. The actor-clock test adds signed event roles and due-date conditions. The document-to-effect test starts with new instrumented reads, and the policy-integrity test extends its fixed scenarios with static-permit current checks and a separately validated typed policy.

The later 46-case comparison is a paired engineering test of the same scenario definitions, not a new held-out set of 46 unrelated legal cases. It creates fresh signatures and output records in each branch. The typed policy's 18 rules and eight selected duties were manually reviewed and fixed. Structural agreement with those records does not itself determine whether the original court order was legally interpreted correctly.

Each module's linked evidence report identifies the original audit and any separate read-only SQL verification. Only the early seven-case saver run lacks an archived raw SQLite database; its Actions artifacts preserve the program-collected SQLite query rows and execution log. Do not combine the SQL-write totals across modules into a pooled outcome rate.
